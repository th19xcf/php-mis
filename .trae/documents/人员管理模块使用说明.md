# 人员管理模块使用说明

> 版本基线：PHP 8.5.4 / CodeIgniter 4.7.4 / Vue 3 + Vite (Soybean Admin) / MySQL
> 文档日期：2026-09-03

***

## 一、模块概览

人员管理模块管理候选人从**邀约 → 面试 → 培训 → 在职**的全流程数据，以及支撑全流程的**人员主档**。

### 数据架构（主档 + 流程实例）

| 表                | 角色   | 说明                            |
| ---------------- | ---- | ----------------------------- |
| `hr_person`      | 人员主档 | 自然人唯一档案（一人一档），姓名/证件号/手机号唯一源   |
| `ee_application` | 流程实例 | 一次应聘一条实例（候选人编码=实例号），跟踪当前阶段状态机 |
| `ee_store`       | 邀约记录 | 邀约阶段增量信息                      |
| `ee_interview`   | 面试记录 | 面试阶段增量信息                      |
| `ee_train`       | 培训记录 | 培训批次/老师/日期等阶段特有信息             |
| `ee_employment`  | 雇佣记录 | 权威表：一人可多条雇佣记录（多次入职），入职次数自动派生  |

设计要点：

- **个人信息唯一源**：姓名、证件号、手机号以主档为权威，各阶段列表/详情通过关联展示；主档修改后全流程生效，同时保留各阶段入阶快照。

- **证件号非强制**：邀约/面试/培训阶段可不采集证件号；**报到（培训→在职转入）时强制校验**，满足薪酬、社保与用工合规要求。

- **入职次数自动派生**：由系统按该员工既有雇佣记录数自动计算（第 N 次入职），无需人工录入。

- **全链审计**：所有增删改操作写入 `hr_audit_log` 字段级审计日志，支持追溯。

### 页面与功能编码

| 页面   | 功能编码 | 数据表            | 路径示例                  |
| ---- | ---- | -------------- | --------------------- |
| 邀约管理 | 2015 | ee\_store      | /personnel/invitation |
| 面试管理 | 2025 | ee\_interview  | /personnel/interview  |
| 培训管理 | 2035 | ee\_train      | /personnel/train      |
| 在职管理 | 2045 | ee\_employment | /personnel/employee   |
| 人员主档 | 2060 | hr\_person     | /personnel/person     |

各阶段页面操作模式一致：**左侧树（按属地/业务/状态/日期分组）+ 右侧详情 + 顶部工具栏**。

## 二、各页面操作说明

### 2.1 邀约管理（2015）

**新增邀约**：工具栏「新增」，录入候选人姓名、手机号、邀约业务、岗位、邀约日期等。系统自动生成候选人编码（格式 `C+日期+序号`，如 C20260903001）。

**查重提示**：新增时若证件号/手机号命中已有主档，系统弹窗提示疑似重复，操作员可选择「关联既有主档」或「新建主档」。

**转入面试**：勾选左侧树人员节点 → 「转入」→ 选择面试日期、面试岗位。转入后：

- 流程实例当前阶段：邀约 → 面试

- 面试表生成新记录，关键字段自动携带

**终止**：邀约拒绝等场景，选择终止原因，实例进入终态。

**统计分析**：工具栏「统计」可查看邀约转化率、渠道分布等。

### 2.2 面试管理（2025）

**转入培训**：勾选人员 → 「转入」→ 选择培训批次、培训老师、培训开始日期。实例当前阶段：面试 → 培训。

**终止**：面试未通过等场景。

**编辑/批量编辑**：详情页修改单条，或勾选多人批量修改面试评价、面试结果等。

### 2.3 培训管理（2035）

**批量修改**：勾选多人 → 「批量修改」→ 统一设置培训批次、老师、日期等。

**转入在职（报到）**：勾选人员 → 「转入」→ 填写岗位类型、结算类型、培训结束日期。

> **证件号强制校验**：转入时系统校验证件号必须已采集；若培训表缺失但主档已有，系统自动回填；两者均缺失则拒绝转入并提示先补采证件号。

转入成功后：

- 雇佣记录表（ee\_employment）生成新雇佣记录，**入职次数自动派生**（同人第二次入职自动为 2）

- 在职管理页面立即可见该员工

- 实例当前阶段：培训 → 入职

**离开**：培训离开场景，选择离开原因，实例终止。

### 2.4 在职管理（2045）

**左侧树**：按属地 → 员工状态（在职/离职）→ 部门 → 班组分组，支持姓名/工号搜索。

**详情**：展示员工全量雇佣信息，姓名、身份证号来自主档（修改请到人员主档页）。

**编辑（SCD2 版本化）**：修改部门、岗位、工号等雇佣属性时，系统保留历史版本（记录开始/结束日期），支持追溯任一时点的信息状态。修改需填写「生效日期」。

**批量编辑**：勾选多人统一修改班组、结算类型等。

**离职处理**：详情页员工状态改为「离职」→ 填写离职日期、离职原因。系统在同一事务内：

- 关闭当前雇佣记录（写入离职信息与记录结束日期）

- 流程实例转入「终止(离职)」

- 保留全部历史供追溯

**删除**：纠错场景软删除，需二次确认；审计日志留痕。

**再次入职**：同一人离职后重新走流程，新雇佣记录自动生成，入职次数 +1；历史雇佣记录不受影响。

### 2.5 人员主档（2060）

**左侧树**：按入职年份/月份分组，支持渠道筛选。

**新增主档**：录入姓名、手机号等必填项；证件号可留空（未采集状态），后续补采。

**查重**：

- 新增时自动软匹配（手机号等），命中弹窗提示

- 详情页「查重」按钮主动检测疑似重复档

**证件号补采**：详情页补录证件号；若与既有主档撞号，系统提示「合并」或「新建」，避免重复建档。

**合并**：将重复主档合并至目标主档 —— 事务内完成流程实例关联迁移、字段合并（按最新验证值为准）、重复档标记「合并至GUID」留痕（不物理删除）。

**删除保护**：主档仍关联邀约/面试/培训/在职/雇佣任一有效记录时，禁止删除，需先处理下游数据或走合并。

## 三、通用功能

### 3.1 数据导入（工作台）

各阶段页面工具栏「导入」按钮（需导入权限）：

1. 下载模板 → 按模板填写（表头与列配置 `def_import_column` 一致）
2. 上传文件，系统自动完成：临时表暂存 → 预处理（编码生成/查重）→ 校验 → 入库
3. 校验失败的行会生成错误报告，修正后可重导
4. 候选人编码按**邀约业务日期**（非录入日期）顺序生成，保证时间线有序

### 3.2 字段配置化

页面字段、可筛选列、可编辑列均由 `def_query_column` 配置驱动，调整字段无需改代码（需管理员维护配置并刷新缓存）。

### 3.3 权限说明

- **属地权限**：列表/树/详情按用户属地授权过滤，仅可见授权属地数据

- **敏感信息**：身份证号、手机号等敏感字段受查看权限控制

- **调试 SQL**：管理员（def\_user.调试赋权=1）可在各页面查看后端实际执行的 SQL 与权限条件，用于问题排查

### 3.4 操作留痕

所有增删改（含批量、导入、流转）写入 `hr_audit_log`：操作类型、变更字段、前后值、操作人、来源、时间。可按人员编码/候选人编码查询全流程操作历史。

## 四、常见问题

**Q1：转入时报"证件号未采集"？**
报到环节强制校验证件号。先到人员主档（2060）补录证件号，再回培训页执行转入；系统会自动回填到培训记录。

**Q2：同一个人重复建档了怎么办？**
人员主档页 → 详情 → 「查重」确认 → 「合并」→ 输入目标主档人员编码 → 确认合并。源档留痕不删除，流程记录全部迁移。

**Q3：员工离职后又回来入职，怎么操作？**
正常从邀约重新发起流程即可。报到时系统识别到同证件号既有雇佣历史，自动生成新雇佣记录并派生入职次数（如第 2 次），历史记录完整保留。

**Q4：修改员工信息后历史数据会变吗？**

- 主档信息（姓名/证件号/手机号）：全流程即时生效，但各阶段入阶快照保留原始值

- 雇佣信息（部门/岗位/工号等）：SCD2 版本化，按「生效日期」生成新版本，历史版本只读保留

**Q5：为什么列表里姓名与阶段表录入时不一致？**
列表姓名取自主档（唯一源）。主档订正后（如错别字修正）列表即显示订正值——这是设计行为；原始入阶值可在阶段记录与审计日志中追溯。

## 五、数据保留与合规

- 未录用候选人信息按个保法要求在保留期（1\~2 年）后清理

- 员工雇佣记录长期留存

- 敏感数据（证件号/手机号）展示脱敏，查看需授权
