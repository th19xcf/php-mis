> **适用范围**：邀约、面试、培训、在职、人员主档五个功能页面（功能编码 2015/2025/2035/2045/2060）

# 第一部分 设计说明

## 1. 设计目标与原则

| 原则      | 落地方式                                        |
| ------- | ------------------------------------------- |
| 自然人唯一建档 | hr\_person 主档 + 证件号唯一索引；一人一档，全流程共享          |
| 个人信息唯一源 | 姓名/证件号/手机号以主档为权威；阶段表仅保留入阶快照                 |
| 流程与身份分离 | 一次应聘一条流程实例（ee\_application），多次应聘互不干扰        |
| 阶段增量存储  | 每阶段表只存该阶段特有字段，跨阶段冗余字段淘汰                     |
| 配置驱动    | 流转字段映射、页面字段、导入列均为配置表驱动，改配置不改代码              |
| 幂等与并发安全 | 唯一索引 + 事务 + FOR UPDATE 行锁 + 状态机条件更新         |
| 全链可追溯   | SCD2 版本化 + hr\_audit\_log 字段级审计 + 合并留痕不物理删除 |
| 合规内建    | 报到强制采集证件号；敏感字段脱敏；未录用数据按保留期清理                |

## 2. 总体架构

```
                    ┌────────────────────────────────────────┐
                    │           hr_person 人员主档            │
                    │  （自然人唯一档：姓名/证件号/手机号/性别/出生日期）│
                    └───────────────┬────────────────────────┘
                                    │ 人员编码（1）
                    ┌───────────────┴────────────────────────┐
                    │        ee_application 流程实例          │
                    │  （一次应聘一条：候选人编码=实例号，状态机）  │
                    └──┬──────────┬──────────┬──────────┬────┘
              邀约阶段 │  面试阶段 │  培训阶段 │  入职阶段 │
          ┌───────────┴──┐ ┌──────┴─────┐ ┌──┴─────────┐ ┌┴──────────────┐
          │   ee_store   │ │ee_interview│ │  ee_train  │ │ ee_employment │
          │  邀约记录     │ │  面试记录   │ │  培训记录   │ │  雇佣记录(权威) │
          └──────────────┘ └────────────┘ └────────────┘ └───────┬───────┘
                                                                    │ 双写镜像(过渡期)
                                                          ┌─────────┴────────┐
                                                          │    ee_onjob      │
                                                          │ 旧在职表(待归档)  │
                                                          └──────────────────┘
```

**核心关系**：

- `hr_person.人员编码` ← 1:N → `ee_application`（一人多次应聘）

- `ee_application.候选人编码` ← 1:1 → 各阶段记录（每实例每阶段最多一条活跃记录）

- `hr_person.人员编码` ← 1:N → `ee_employment`（一人多次雇佣，入职次数派生序号）

- 全链统一以 `人员编码`（主档）+ `候选人编码`（实例）双键关联，**不使用证件号做 JOIN 键**

### 3.4 阶段记录表（ee\_store / ee\_interview / ee\_train）

只存**该阶段特有**字段 + 入阶快照：

- `ee_store`：邀约业务、邀约岗位、邀约日期、招聘渠道/渠道类型/渠道名称

- `ee_interview`：面试业务、面试岗位、各轮面试日期/面试人/结果、预约培训日期

三表均带：候选人编码、人员编码、姓名/身份证号/手机号码（入阶快照）、属地快照、审计五列（操作记录/来源/人员/时间/有效+删除标识）。

### 3.5 ee\_employment 雇佣记录表（阶段③新增，权威表）

| 字段组  | 列                                          | 说明                                       |
| ---- | ------------------------------------------ | ---------------------------------------- |
| 关联键  | 人员编码、候选人编码、入职次数                            | 入职次数=派生序号，服务端按活跃记录数+1 计算                 |
| 入阶快照 | 属地、招聘渠道、员工类别、实习结束日期、培训信息/开始/完成日期、一阶段/二阶段日期 | 入职时点冻结，VARCHAR 原样快照                      |
| 雇佣业务 | 部门编码/名称、班组、小组、岗位名称/类型、结算类型、工号1/2、派遣公司、备注   | 随在职周期可更新（SCD2 版本化）                       |
| 阶段跟踪 | 员工阶段、员工状态                                  | 在职/离职                                    |
| 生命周期 | 记录开始日期、记录结束日期、离职日期、离职原因                    | **DATE 类型；记录结束日期 NULL=在职**；SCD2 版本失效不写此列 |
| 审计列  | 操作记录/来源/人员、开始/结束/操作时间、校验/删除/有效标识           | 时间列升级 DATETIME                           |

**唯一索引（幂等核心，MySQL 8.0.13+ 函数索引）**：

```sql
UNIQUE KEY `uk_候选人编码_活跃` ((CASE WHEN 有效标识='1' AND 删除标识='0' THEN NULLIF(候选人编码,'') END))
UNIQUE KEY `uk_人员编码_次数_活跃` (人员编码, (CASE WHEN 有效标识='1' AND 删除标识='0' THEN 入职次数 END))
```

含义：同一候选人编码只允许一条活跃雇佣记录（防重复报到）；同一人同一入职次数只允许一条活跃记录（防并发派生撞号）。函数 CASE 对失效/软删行返回 NULL，不占用唯一性。

**设计约定**：

- 姓名/身份证号/手机号码**不入本表**，读时 JOIN hr\_person（主档权威）

- 存量迁移决策（2026-09-03 确认）：ee\_onjob 11464 条 SCD2 失效版本行不迁移（随旧表归档），仅迁 6666 条活跃行

- 记录删除=纠错而非雇佣结束，**不写记录结束日期**

### 3.6 ee\_onjob（过渡期镜像表）

阶段③双写期的旧表：权威写落 ee\_employment 后，同事务镜像写 ee\_onjob，保证尚未切换的历史消费方继续可用。④写切换后停写，⑤归档（RENAME ee\_onjob TO ee\_onjob\_arch\_YYYYMMDD）。

### 3.7 配置表

**def\_seq（发号器）**：复合主键（序列名，日期），按日分桶发号。

**def\_stage\_transfer（流转映射）**：

```sql
源表 | 目标表 | 源列 | 目标列 | 默认值 | 排序 | 有效标识
```

- `源列` 为空 + `默认值` 以 `@` 开头 → 取流转表单参数（如 `@面试日期`）

- `源列` 以 `expr:` 开头 → SQL 表达式（如跨表取值 `IFNULL(t2.招聘渠道,"")`）

- 其余 → 直接源列 → 目标列复制

**def\_query\_column / view\_function**：按功能编码配置页面字段（字段名/查询名/顺序/可编辑），驱动列表、详情、筛选。

DDL 明确约定「姓名/身份证号/手机号码等自然人信息不入本表」。仅存双关联键（候选人编码+人员编码）+ 实例级信息：当前阶段（状态机）、五个阶段日期戳（邀约/面试/参培/入职/终止日期，全流程时间线）、终止原因。

**ee\_store（邀约）—— 快照最全的阶段表**

姓名/身份证号/手机号码/性别/属地 快照 + 招聘渠道三列（渠道类型/招聘渠道/渠道名称）首采。邀约是流程信息采集起点，故快照字段最多。

**ee\_interview（面试）—— 中等快照**

姓名/身份证号/手机号码/属地 快照 + 渠道三列复制 + 实习结束日期首采（学籍属性，随应聘批次走）。

**ee\_train（培训）—— 最小快照**

仅 姓名/身份证号/手机号码/属地 四列快照（转入在职时证件号强制校验的数据源之一）。

**ee\_employment（雇佣记录）—— 零自然人信息（新架构核心约定）**

完全不存姓名/证件号/手机号码，读时 LEFT JOIN hr\_person 获取（个人信息唯一源）。仅保留四项入阶快照：属地（继承自 ee\_train）、招聘渠道（流转时自 ee\_store 取）、员工类别（按渠道派生：校招=未毕业学生/其他=合同制员工）、实习结束日期（流转时自 ee\_interview 取）。

**ee\_onjob（旧在职表）—— 全冗余**

旧宽表存 姓名/身份证号/手机号码/属地/招聘渠道/员工类别/实习结束日期 全量冗余，是历史上「四宽表信息复制导致不一致」问题的根源；随阶段④⑤下线归档。

**读取路径**（哪个页面从哪取人名）：在职管理列表/详情的姓名、身份证号均实时 JOIN 主档；邀约/面试/培训页面读单表快照（阶段表自身列）；主档页直读权威值。**修改入口统一在人员主档页**，主档订正后全流程列表即时生效，各阶段入阶原始值保留在快照列可追溯。

**写入路径**（信息何时被采集/复制）：

```
邀约新增 ──首采──→ hr_person（权威档）+ ee_store 快照 + ee_application 实例
邀约转面试 ──流转──→ ee_interview 复制快照（def_stage_transfer 配置）
面试转培训 ──流转──→ ee_train 复制快照
培训转在职 ──报到──→ ee_employment（仅双键+四快照，自然人信息不复制）
证件号补采 ──主档页──→ hr_person 回填 + 派生性别/出生日期
```

## 4. 编码体系（候选人编码）

- **格式**：`C + YYYYMMDD + 3 位序号`（如 `C20260903001`），日容量 999

- **业务日期**：按**邀约业务日期**（非录入日期）分桶发号，保证时间线与编码字典序一致

- **并发控制**：`sp_生成候选人编码` 存储过程内 `INSERT IGNORE` 确保 def\_seq 当日行存在 + `LAST_INSERT_ID()` 原子取号，多用户导入/录入不冲突

- **不回收**：事务回滚产生的跳号可接受，序号不复用（可追溯性优先）

- **PHP 入口**：`CandidateCodeService`（单个发号 + 批量按日期分桶预取号段）

## 5. 流程状态机

```
邀约 ──→ 面试 ──→ 培训 ──→ 入职 ──→ 终止(离职)
  │        │        │        │
  └────────┴────────┴────────┴──→ 终止(各阶段原因)
```

| 当前阶段 | 允许目标       |
| ---- | ---------- |
| 邀约   | 面试、终止      |
| 面试   | 培训、终止      |
| 培训   | 入职、终止      |
| 入职   | 终止         |
| 终止   | （终态，不可再流转） |

**实现**（[ApplicationService.php](file:///e:/code/php/mis/backend/app/Services/Application/ApplicationService.php)）：

- `STAGE_FLOW` 白名单校验，非法转换抛异常并回滚整个事务（连阶段表 INSERT 一起回滚）

- 流转 UPDATE 带条件 `当前阶段=:fromStage` —— 重复提交 0 行生效（幂等）

- 状态变更与时间戳、终止信息、审计日志在同一事务内

- `createInstance` 用 NOT EXISTS 幂等：实例已存在则跳过不报错（兼容重试）

## 6. 阶段流转机制

流转 = 配置驱动的 `INSERT...SELECT`（[StageTransferService.php](file:///e:/code/php/mis/backend/app/Services/Application/StageTransferService.php) 消费 def\_stage\_transfer），三段映射如下：

**邀约 → 面试**（ee\_store → ee\_interview）：候选人编码/人员编码/姓名/身份证号/手机号码/属地/招聘渠道三列直传；邀约业务→面试业务、邀约岗位→面试岗位；表单参数 @面试日期/@面试人/@面试结果/@预约培训日期 写入一次面试各列；邀约信息默认「通过」。

**面试 → 培训**（ee\_interview → ee\_train）：个人信息六列直传；@培训业务/@培训批次/@培训老师/@培训开始日期/@预计完成日期 表单写入；培训状态默认「在培」；面试信息默认「有」。

**培训 → 雇佣记录**（ee\_train → ee\_employment）：个人信息直传；`expr:` 跨表取值——招聘渠道自 ee\_store（t2）、员工类别按渠道派生（校招=未毕业学生/其他=合同制员工）、实习结束日期自 ee\_interview（t3，学籍属性随实例）；@岗位类型/@结算类型 表单写入；一阶段日期=培训完成日期；员工状态默认「在职」；记录开始日期=@培训结束日期；**入职次数服务端派生，不接受前端传参**。

## 7. 幂等与并发控制

| 机制               | 场景                                         |
| ---------------- | ------------------------------------------ |
| 函数唯一索引           | 重复报到 / 并发派生入职次数撞号 → 1062 → 整事务回滚           |
| FOR UPDATE 行锁    | 编辑/离职前锁定旧行快照，并发编辑互斥                        |
| 条件 UPDATE        | 状态机流转带 `当前阶段=:from` 条件，重复提交 0 行生效          |
| NOT EXISTS       | createInstance / 配置 INSERT 防重              |
| 事务包裹             | SCD2（失效旧行+插入新行）、双写（权威+镜像）、流转（实例+阶段表）均为原子操作 |
| LAST\_INSERT\_ID | 发号器原子取号                                    |

## 8. SCD2 版本管理（雇佣信息编辑）

修改部门/岗位/工号等雇佣属性时（[EmployeeService::updateEmployee](file:///e:/code/php/mis/backend/app/Services/Employee/EmployeeService.php)）：

1. 事务开始 → FOR UPDATE 锁定活跃行 + 全列快照
2. 失效旧行：有效标识=0，记录结束日期=生效日期，操作记录「更新,xxx」
3. INSERT 新行：复制全部业务列 + 新值，记录开始日期=生效日期
4. ee\_employment 权威行**就地 UPDATE**（不做 SCD2 —— 对齐「当前值就地更新+字段级审计」约定，减少查询负担）
5. 审计日志记字段级 diff

顺序要点：先失效旧行再插入新行，避免与函数唯一索引冲突。记录开始日期在 SCD2 新版本行复制原值**不漂移**（记录真实雇佣开始日）。

## 9. 权限与数据安全

| 机制   | 实现                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------- |
| 属地权限 | 登录时（Auth.php）从 `def_user.属地赋权` 计算 `location_authz` 写入会话；查询时经 ContextService 生成 SQL 条件，列表/树/详情统一过滤 |

| 删除保护 | 主档删除前检查五张下游表（邀约/面试/培训/在职/雇佣）有效关联，有则拒绝                                                             |

## 10. 阶段③双写与切换架构

```
写入路径（当前）：
  培训转入 ──同事务──→ ee_employment INSERT（权威，入职次数派生）
                 └──→ ee_onjob     INSERT（镜像）
  离职     ──同事务──→ ee_employment UPDATE（关活跃行）
                 └──→ ee_onjob     UPDATE（关版本行）
  编辑/批改 ──同事务──→ ee_onjob SCD2 版本化
                 └──→ ee_employment 就地 UPDATE（EmploymentMirrorService）
  删除     ──同事务──→ ee_onjob 软删
                 └──→ ee_employment 镜像软删

读取路径（已切换）：
  列表/树/详情 → ee_employment（派生表内属地过滤）+ LEFT JOIN hr_person
  GUID 语义    → ee_employment.GUID（编辑/离职/删除定位链同步适配）
```

- 镜像服务：[EmploymentMirrorService.php](file:///e:/code/php/mis/backend/app/Services/Employee/EmploymentMirrorService.php)（利用请求级共享连接——调用方有事务则自动同事务）

- 工作台防御性挂点：RecordEditService / BatchEditService 共 9 处（当前 def 配置 ee\_onjob 可修改=0 不可达，放开配置即自动双写）

- 对账：`employment:reconcile` 六项核验（镜像缺失/权威孤儿/字段差异/序号漂移/生命周期规格/主档孤儿）

## 2. 配置维护

### 2.1 新增/调整流转字段映射（def\_stage\_transfer）

1. 查询现有映射：`SELECT * FROM def_stage_transfer WHERE 源表='ee_train' ORDER BY 排序`
2. 增行：源列/目标列/默认值（`@` 前缀=表单参数，`expr:` 前缀=SQL 表达式）
3. **无需改代码**，StageTransferService 动态消费
4. 注意：目标列必须在目标表实际存在（否则 INSERT 报未知列）

### 2.2 页面字段调整（def\_query\_column / view\_function）

按功能编码（2015/2025/2035/2045/2060）增删字段行；调整后**需刷新元数据缓存**。详情页字段若分布在多表，走 `buildDetailSelectFieldsMulti`（按「别名→表列」自动归属定位）。

### 2.3 导入列配置（def\_import\_column）

列：列名/字段名/查询名/顺序/字段类型/校验类型/导入类型/缺省值。**禁止配置空列名或空字段名**（会导致临时表 Incorrect column name 错误）。

### 2.4 缓存刷新

元数据缓存（MetadataCache）在配置变更后需刷新；`Mcommon::select` 有请求级缓存，长任务脚本（迁移等）需用 `getDb()->query()` 直连绕过。

## 3. 数据治理

### 3.1 重复主档处理

- **发现**：新增时自动软匹配（手机号）/ 详情页「查重」按钮（证件号硬命中 + 手机号软命中）

- **处置**：合并向导（PersonApi::merge）——事务内完成：流程实例关联迁移 + 字段合并（按最新验证值为准）+ 源档写「合并至GUID」留痕

- **原则**：不物理删除；手机号只软提示不阻断（家属共用场景）

### 3.2 数据保留

| 数据               | 保留策略                  |
| ---------------- | --------------------- |
| 未录用候选人（流程终止且未入职） | 保留期 1\~2 年后清理（按个保法）   |
| 员工雇佣记录           | 长期留存                  |
| SCD2 失效版本        | 长期留存，量大后可考虑定期归档提升查询性能 |

### 3.3 孤儿数据

对账命令会暴露：权威孤儿（ee\_employment 有、镜像无——补迁或人工核对）、主档孤儿（无主档关联——按人员编码锚点核查）。处置前一律留审计痕迹。

## 4. 升级路线（阶段③ → ④ → ⑤）

| 阶段   | 动作                                                                      | 准入门禁               | 回退方式            |
| ---- | ----------------------------------------------------------------------- | ------------------ | --------------- |

## 5. 故障排查

| 现象                        | 定位                            | 处置                                             |
| ------------------------- | ----------------------------- | ---------------------------------------------- |
| 转入报 1062 重复键              | uk\_候选人编码\_活跃 命中              | 检查是否重复提交；确认该候选人已有活跃雇佣记录                        |
| 转入报「证件号未采集」               | 报到强制校验（P1-2）                  | 先到主档页补录证件号，再回培训页转入                             |

# 第三部分 使用说明

## 1. 页面总览

| 页面   | 功能编码 | 数据表            | 路径                    |
| ---- | ---- | -------------- | --------------------- |
| 邀约管理 | 2015 | ee\_store      | /personnel/invitation |
| 面试管理 | 2025 | ee\_interview  | /personnel/interview  |
| 培训管理 | 2035 | ee\_train      | /personnel/train      |
| 在职管理 | 2045 | ee\_employment | /personnel/employee   |
| 人员主档 | 2060 | hr\_person     | /personnel/person     |

各阶段页面布局一致：**左侧树**（属地/业务/状态/日期分组，支持搜索）+ **右侧详情** + **顶部工具栏**（新增/修改/批量修改/删除/转入/导入/调试）。列表数据按用户属地授权自动过滤。

## 2. 邀约管理（2015）

- **新增邀约**：录入姓名、手机号、邀约业务、岗位、邀约日期 → 系统生成候选人编码（C+邀约日期+序号）并自动建档（软查重命中时选择关联既有主档或新建）

- **转入面试**：勾选人员 →「转入」→ 填面试日期/面试人/结果/预约培训日期；实例阶段 邀约→面试

- **终止**：邀约拒绝等场景，选择原因，实例终态

- **统计**：邀约转化率、渠道分布

- **查重**：证件号/手机号命中提示

## 3. 面试管理（2025）

- **转入培训**：勾选 →「转入」→ 填培训批次/老师/开始日期/预计完成日期；实例 面试→培训

- **编辑/批量编辑**：面试评价、面试结果等

- **终止**：面试未通过等场景

## 4. 培训管理（2035）

- **批量修改**：统一设置批次/老师/日期

- **转入在职（报到）**：勾选 →「转入」→ 填岗位类型/结算类型/培训结束日期

  - **证件号强制校验**：培训表缺失但主档已有则自动回填；两者均缺则拒绝并提示先补采

  - 转入成功：生成雇佣记录（**入职次数自动派生**），在职页立即可见，实例 培训→入职

- **离开**：选择离开原因，实例终止

## 5. 在职管理（2045）

- **左侧树**：属地 → 员工状态 → 部门 → 班组；姓名/工号搜索

- **详情**：姓名/身份证号来自主档（修改请到人员主档页）；雇佣信息来自 ee\_employment

- **编辑**：修改部门/岗位/工号等需填「生效日期」，系统 SCD2 版本化保留历史

- **批量编辑**：勾选多人统一修改班组/结算类型等

- **离职处理**：员工状态改「离职」+ 离职日期/原因 → 同一事务关闭雇佣记录 + 实例转「终止(离职)」

- **再次入职**：同一人重新走流程，报到自动生成新雇佣记录，入职次数+1，历史不受影响

- **删除**：纠错场景软删除，二次确认，审计留痕

## 6. 人员主档（2060）

- **新增**：姓名/手机号必填，证件号可空（后续补采）

- **查重**：新增自动软匹配；详情页「查重」主动检测

- **证件号补采**：撞号时提示「合并」或「新建」

- **合并**：输入目标主档人员编码 → 事务内迁移流程关联 + 字段合并 + 源档留痕（不物理删除）

- **删除保护**：仍关联任一有效阶段/雇佣记录时禁止删除

## 7. 数据导入

1. 工具栏「导入」（需权限）→ 下载模板（表头与 def\_import\_column 一致）
2. 上传 → 临时表暂存 → 预处理（编码生成/主档匹配：证件号硬命中、手机号软命中）→ 校验 → 入库
3. 校验失败行生成错误报告，修正后重导
4. 候选人编码按**邀约业务日期**顺序生成；多用户并发导入不冲突（发号器原子取号）

## 8. 常见问题（用户视角）

**Q1 转入报"证件号未采集"？** 到人员主档（2060）补录证件号后回培训页转入，系统自动回填。

**Q2 重复建档了怎么办？** 主档页 → 详情 →「查重」确认 →「合并」→ 输入目标人员编码 → 确认。源档留痕不删除。

**Q3 离职员工再回来入职？** 从邀约重新发起流程。报到时自动识别既有雇佣历史，生成新雇佣记录（第 2 次），历史完整保留。

**Q4 改员工信息后历史会变吗？** 主档信息（姓名/证件号/手机号）全流程即时生效但入阶快照保留原始值；雇佣信息按生效日期版本化，历史只读。

**Q5 列表姓名与当初录入不一致？** 列表取主档权威值，主档订正后（如错别字）即时生效——设计行为；原始值可追溯（入阶快照 + 审计日志）。

**Q6 为什么入职次数不用填了？** 系统按该员工既有雇佣记录自动派生（阶段③起，前端已下架输入项）。
